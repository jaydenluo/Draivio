# 批量处理

顶部文件操作区选择「批量处理」，可选多张图片或递归读取一个文件夹。批处理独立于编辑文档，不读取/修改主画布，不调用云服务或付费 AI。

1. 选择 PNG、JPEG、WebP 文件。文件夹内其它文件与符号链接会跳过；每批最多 1000 项。
2. 设置按长边缩放，或固定宽高。固定尺寸「适配」保留全图并留透明边（JPEG 为白色），「填充」居中裁切。
3. 设置输出格式、JPEG/WebP 压缩质量和原色/黑白/暖色/明亮预设。「文档调整预设」可复用 F13 的内置中性/暖调和当前文档已保存的 HSL/色彩平衡预设，像素处理复用编辑器统一调整管线。选定预设参数会嵌入批处理配方，之后原预设变化不会改变已存配方。可叠加文字或本地图片水印，设置位置、透明度、比例与边距。
4. 选择一个样例并预览。预览以完整输出尺寸运行与最终导出相同的处理和编码，不另做近似预览。修改参数或样例会使预览失效，须重新预览。
5. 选择输出目录，开始。输入与输出每张最多 8MP，压缩输入最多 32MB；图片水印最多 2MB / 1MP。并发默认为 1，最高 2，因此不会同时解码整批图片。PNG/WebP 保留透明像素；JPEG 使用白底。

输出名为 `原名-batch-序号.扩展名`，如 `photo-batch-001.png`。存在同名文件时另加 `-2`、`-3` 等，不覆盖已有文件。桌面使用选定目录权限令牌与 `persist_noclobber` 原子写入，写入失败不会截断原文件；目录权限失败后可重新选择。

取消会停止安排新项，正在处理的最多两项完成后保留输出。损坏文件仅令该项失败，不影响其余项。结果列出每项状态、尝试次数、失败原因、实际输出路径与成功/失败/取消汇总。「仅重试失败项」保留成功项；改变步骤后需要恢复原配方再重试，或显式开始新批次。

配方以版本化 JSON 存在本机浏览器存储，含图片水印本身（无需原水印文件）。输入文件/输出目录权限不属于配方，下次打开须重新选取；最多保留 20 个命名配方。浏览器版本要求 `showDirectoryPicker`，不支持时显示具体能力反馈。浏览器文件 API 无排他创建，采用写入前查重；桌面应用提供原子防覆盖保证。浏览器外部程序在查重与创建之间同时创建同名文件的极窄竞态不受文件 API 保护。

色彩说明：本流程针对浏览器解码后的 8 位 sRGB 图片，不保留输入 ICC/EXIF 等元数据，不适用于印刷级 ICC 或 16 位批处理。输入 JPEG 的浏览器解码会应用方向标记。

验证包括固定像素 PNG 横竖适配/裁切、透明边、真实文字/图片水印像素、配方重用输出字节、JPEG/WebP 真实编码、质量差异、队列并发/取消/损坏/失败重试、目录重名/路径穿越/写入失败，以及对话框关键交互。真实画布测试使用测试依赖 batch-test-canvas（@napi-rs/canvas 的包别名，避免改变 jsdom 的全局 Canvas 能力），生产运行仍使用环境原生 Canvas。
