# macOS 本机 OCR 与文字替换

Composer 的「识字与文字替换」支持两条路径：已有文字层可明确选择文字对象后直接替换，不调用识字或生图；普通扁平图像使用 macOS Apple Vision `VNRecognizeTextRequest`（accurate / zh-Hans、zh-Hant、en-US），提取文字、置信度和四边形。

必须选择位置。置信度小于 80% 还须核对确认。识字不推断字体；系统无衬线是用户明确选择的替代字体，可另选字体和颜色。本工具不把 FontFaceSet.check 当作安装证明；所有非通用原字体和预设字体均标明未验证，预览前必须明确确认其缺失时可能回退，或选择通用替代字体。更换字体/目标或取消会清除确认。使用「预览文字修补」检查前后画布，确认后产生独立修补层和可编辑文字层；一次撤销恢复原作品。原图资源保留。预览、取消、失败和过期结果不会写入项目。

修补使用仓库已有的本地邻域纹理算法，不是生成式模型；仅作用于选中字框及 2px 边缘，其他已识别文字禁止填充或采样。最多 16384 待填像素、4194304 文档像素；采样在字框周围24px内，按计算预算限制为32–256像素。复杂背景、重叠文字、标志附近的识别错误仍需人工检查；达不到边界/时间/像素预算会明确失败，不创建伪修补。段落框、旋转、替代字体、行距和对齐参数保存于普通文字层，后续可用属性面板继续调整。

## 系统与分发

macOS 构建通过已安装的 Apple Swift SDK 编译系统 Vision helper，嵌入 Tauri 二进制，运行时在私有临时目录以0700权限执行并清理。请求为 PNG，限制24MB / 4194304像素，执行30秒超时，读取输出有大小限制。无需安装 Swift 运行时、下载模型、API密钥或调用付费服务；没有把 Apple 模型文件复制进仓库。框架属于 macOS，构建使用本机已安装 Apple SDK 的许可条款；这不等于对最终应用签名/公证作出许可保证。当前真实验证是本机arm64开发构建，发布签名、公证沙箱和Intel机器仍须在发布流程验证。非macOS桌面和浏览器预览明确显示无后端，不伪造候选。

识字只生成临时预览数据。项目保存修补PNG和可编辑文字，不保存临时helper、识字服务地址或外部凭据。

## 可重复的真实证据

样本由本仓库脚本原创绘制，含简体中文、两个同价、英文和约-7.7°倾斜中文。模型不下载，推理不联网，调用成本0。系统识别结果与OS版本有关；仓库固定JSON是本次实测，不是准确率保证或替代后端。

```sh
node scripts/ocr/verify.mjs /tmp/draivio-ocr-evidence
OCR_EVIDENCE_DIR=/tmp/draivio-ocr-evidence npx vitest run src/ai/vision/ocr.native.integration.test.tsx
cargo test --manifest-path src-tauri/Cargo.toml ocr::tests -- --nocapture
```

真实像素集成测试运行 helper、修补第一处¥99→¥129、保留第二处¥99和其它文案、保存后重开资源与文字、验证一次撤销；还修补倾斜中文并写出保持旋转的「替换中文」。固定前后PNG、原始识字四边形/置信度和修补统计位于 `docs/evidence/ocr-native/`。

交互测试中的native识字、栅格化和修补结果是隔离边界的测试替身，用于验证选择、低置信度、取消、失效和提交逻辑；不充当真实模型证据。`OCR_EVIDENCE_DIR` 未配置时真实像素测试明确跳过，运行以上命令才有真实证据。

另有 `--complex` 自制变体（价格后方渐变/细线纹理和独立 LOGO），可用 `node scripts/ocr/verify.mjs /tmp/draivio-ocr-complex --complex` 后设置该目录运行同一真实集成测试。固定证据在 `docs/evidence/ocr-native/complex/`。这个样本验证局部修补不会修改字框外与LOGO区域像素；纹理局部可能出现接缝，不能概括成任意复杂背景修复质量保证。
